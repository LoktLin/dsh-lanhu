# 读稿：三种视图与关键列

> 返回 [README](../README.md) ｜ 完整参数见 README 的「工具」一节。

## 读稿：三种视图

| 视图 | 用途 | 一句话 |
|---|---|---|
| **块级清单** `blocks` | 还原时最常看 | 几百个图层 → 一百多个「块」，每块带齐属性，还单独列出**分割线** |
| **区域表** `region` | 抠某个区块的图层（替代手写抠图脚本） | 内边距已按父子坐标算好；可加 `limit` 看全量 |
| **全量** `format=full` | 落盘 JSON，程序化消费 | 扁平数组，字段见下 |

### 三张表里"最容易漏"的列

数据层一直有、但以前**不打出来就等于不存在**的几项，现在都在表里：

| 列 | 含义 | 为什么要看 |
|---|---|---|
| **不透明** | 图层 `opacity`，**已累乘祖先链** | 半透明的"厚度层 / 底纹"漏读会被做成生硬实心块。注意它和填充色 `@xx%`（**填充 alpha**）是**两回事**，两者独立叠加 |
| **字体** | `font.family` 短名 | 一个封面用 3 种字体是常态；漏读就全站一个字体 |
| **行高·字距** | 形如 `22/0.5` | 排版还原的关键，缺失只能靠猜 |
| **底色/填充** | 多段渐变串成 `#a@18%→#b@10%`；只有描边的层标 `描边 #xxxxxx` | 渐变只打第一个 stop 是**最隐蔽**的坑：表格里"有颜色"，看着不缺信息 |

> 实测：某 1920×1080 大屏稿（711 层）全稿 **55 层多段渐变**、**48 层半透明** —— 不扫这两类直接开工会返工。

### 坐标映射（把设计稿坐标搬进你的坐标系）

```bash
lanhu read --project <pid> --image <iid> --region 170,680 \
  --map-box "659.32,120.58,1271.64,651.53" \   # 设计稿参照框
  --to-box  "4,4,442.3,480.3"                  # 目标参照框（如你的 SVG viewBox）
```

输出多两列「映射 x,y / 映射 w×h」。**x/y 各自独立缩放（非等比）** —— 两个坐标系长宽比不同也能对上。

---

> **手上没有设计稿、只有原型？** 原型页面的样式也能读（`format:"layers"`），见 [产品文档.md](产品文档.md) 与 [原型样式.md](原型样式.md)。
> 但原型里的色值/字号是设计者随手填的，**成色不如设计稿**，别拿它代替设计稿。

## 支持与不支持的稿件格式

蓝湖的稿子**不止一种图层树结构**。接稿前先知道手里是哪一种，能省掉一整轮"读出来是空的"的误会。

| 稿件格式 | 怎么认 | 支持情况 |
|---|---|---|
| **Figma / Sketch 常规稿** | 图层树里有 `artboard` | ✅ 完整支持 |
| **Sketch 插件导出** | 顶层 `type: "sketchPlugin"`：图层**平铺在 `info[]` 里**、没有 `artboard`，层级靠 `parentID` | ✅ 2026-10 起支持：归一化成与常规稿**同形**的树，之后走完全同一条解析链（块级清单 / 区域表 / diff / 审计 / 切图全都可用） |
| **Axure 原型 / 产品文档** | 树里有 `pages` / `sitemap` | ⚠️ 那不是设计稿：改用 `lanhu_read_product_doc`（拿设计稿解析器读它会**报错点名**，不会给空结果） |
| **认不出的树** | 既没有 `artboard`、也没有 `info[]`、也没有 `pages` | ❌ 明示 `unsupported: true` + `sourceFormat: "unknown"` |

### Sketch 插件格式：实测出来的字段映射（不是猜的）

实测来源：项目「105福建省碳足迹公共服务平台」（252 张稿），其中 **11/20 是这种格式**，`info[]` 规模 45~340 项。

| `info[]` 里的字段 | 归一化后 | 怎么确认的 |
|---|---|---|
| `left` / `top` | `frame.left/top` | 是**画板绝对坐标**：44 个有父层的元素里 **24 个**的 left/top 超出父层局部框——父局部框根本装不下，所以不可能是"相对父级" |
| `opacity`（**0..100**） | `opacity`（0..1） | 实测 `opacity: 80` 就是 80% |
| `radius`：`[4]` 或 `[4,0,16,0]` | `radius.{topLeft,topRight,bottomRight,bottomLeft}` | 与 `points[].cornerRadius` **逐值一致**（2348 层无例外） |
| `fills`（顶层） | `style.fills` | 色值对象同形（都带 `value: "rgba(...)"`） |
| `fills[].gradient.colorStops` | `gradient.stops` | **字段名不同**；不迁移会**整条渐变丢掉**（本项目实测 103 处渐变） |
| `borders[].thickness` + `position` | `style.borders[].widths`（四边同宽）+ `lineAlignment` | Sketch 的边框**没有每边宽度** |
| `font.content/size/line/kerning/font` | `text.style` | 字体族名由 `postScriptName` **去掉字重后缀**（`SourceHanSansCN-Bold` → `SourceHanSansCN`，字重 Bold→700） |
| `type: "bitmap"` / `image.imageUrl` | `hasExportDDSImage` / `hasExportImage` | ⚠️ **不能**拿 `hasExportDDSImage` 当切图判据：**890/2348 层**都带它（连普通 `shape` 也有，蓝湖给每层都导了图），照抄会让七成形状都变成"图片块" |
| `ddsType: rectangle / oval` | `paths[0].type: rect / ellipse` | 常规稿实测只出现这两种 |
| `ArtboardID` 那一项 + `position_x/position_y` | 画板 `frame` | 画板的 `left/top` 恒为 0，**画布绝对坐标**在 `position_x/position_y` |

**如实说清拿不到什么**：Sketch 的 `shadow` / `blur` 原样保留但不参与块模型；`star` / `shape-group` 没有对应的 Figma 形状类型（**不编一个出来**）；
Sketch 的边框没有每边宽度，所以这类稿里的**单边分割线只能靠"1px 高的实心条"识别**（Sketch 里本来也是这么画的）。

### 读不出来时，插件**明说**（绝不静默成功）

以前遇到认不出的树，`read_blocks` 会输出「共 **1** 块：画板 1」+ 一张空表 —— **看着跑成功、其实一个块都没解析出来**，
AI 会据此认定"这张稿是空的"，然后什么都不建。现在改成明说：

- **人读文本**说清三件事：这是什么格式 / 本次为空**不代表**这张稿是空的 / 下一步做什么（换一张稿、让设计师重导、只要图就用 `lanhu_download_slices`）；
- **返回对象**带机器可读标志：`unsupported: true`、`sourceFormat`（`"sketchPlugin"` / `"unknown"`）、`code`
  （`SKETCH_PLUGIN_NO_LAYERS` / `UNKNOWN_TREE_FORMAT`）、`ok: false`。**不用读文本就能判断**。

正常读出来、但来源是 Sketch 插件格式时，返回里会带 `sourceFormat: "sketchPlugin"`，文本开头也有一段来源交代
（写清哪些数值是映射来的）—— 普通稿**不带这个字段**，输出与以前逐字节一致。

## 接稿时的三条核对

1. **接稿先扫三列**：「不透明」「字体」「行高·字距」，再确认渐变是完整的（带 `→`）——
   这两分钟能挡掉一整类"做出来才发现"的错误：半透明厚度层被做成实心、全站变成一个字体、多段渐变被压成纯色。
2. **核对"这个图层到底有没有切图"**：设计稿里是矢量的图层（`hasImage=false`）蓝湖**不会导出切图**，
   随便找个图标顶上，风格一眼就不对。
3. **间距取值拿相邻块的坐标相减**，不要凭感觉写百分比；并且内部间隙要小于列间隙，别把关系写反。

## 切图密度：机制在，但**实测配不上**（别指望它给数值）

`lanhu_download_slices` 的 `mapping.json` 里每张图带 `density.effectiveDensity`（实际像素 ÷ 渲染尺寸）
与 `resolutionLimited`（是否低于目标倍率），并在不合格时**直接打印警告**。
目标倍率默认取设计稿自带的 `meta.sliceScale`（实测某稿是 4）。

**但实测这份稿 12 张切图配到 0 张**，两个原因：

| 现象 | 实测数据 |
|---|---|
| 素材带额外留白 | 图层 `48×56`×4 应为 `192×224`，实际素材是 **`200×244`** |
| 同尺寸图层重复 | 4 个 `20×20` 图层都对应 `80×80`，按「唯一才认」必须拒绝 |

根因在数据侧：竞品算得出密度是因为它的通道带 `asset.render_bounds`；
**我们这条通道的 `tree.assets` 是裸 URL 数组**，既没有渲染边界，也没有与图层 id 的对应关系。

所以当前行为是：**`effectiveDensity` 为 `null` + `matchReason` 写明原因**（
`ambiguous` / `no-layer-match` / `slice-scale-unavailable`），**宁可不给，也不给一个错的密度**。

> 因此「切图够不够清晰」这件事，目前仍然只能靠：**看 `f.width/height` 与图层尺寸自己判断**，
> 或让设计师重导。判读时注意 **`null` 与 `[]` 的区别**：
> `densityLimited: null` = **一张都没能评估**（本通道的 `tree.assets` 是裸 URL，没有 `render_bounds`，实测 12/12 都配不上）；
> `densityLimited: []` = 评估过了且**都达标**。把 `null` 读成"达标"就是反的。

## 输出里新增的几段（2026-09-30）

读完稿子后，结果尾部/标题行会多出这些东西 —— 都是**可以直接抄进 CSS** 的，不用再手算：

| 段 | 出现位置 | 说明 |
|---|---|---|
| **「间距一览（可抄 CSS）」** | `read_blocks` 与 `read_design`(summary) 末尾 | 块与块的**最近边距 + 方向**（`↕` 上下 / `↔` 左右），以及**齐平**关系（`≡`，如「说明块底 ≡ 头像底」）。几何与 `region` 的 `gapMaxDistance` **同一套算法**，换个入口看结果一致。**贴边（0px）不计入**（那是"相邻"不是"间距"），按距离从紧到松排。 |
| **双单位** | 「间距一览」与 `region` 输出 | `120×152px / 240×304rpx`。换算比**按画板宽度**算：`rpx = px × 750 ÷ 画板宽`（宽 375 的稿即 ×2），段头会写明用的是哪个基准。想让**宽表**（关键容器 / 块级清单的尺寸列）也双单位，加 `dualUnits`（工具）/ `--dual-units`（CLI）—— **默认关**，免得每行撑到 200+ 字符。 |
| **色值的可粘贴形式** | 三张表的填充/底色列 | `#574af4@10% (rgba(87, 74, 244, 0.1))` —— 保留原串便于回查，同时给能直接粘进 CSS 的形式。不透明色不附括号（纯噪音）。 |
| **标题行的溯源** | 各模式的标题行 | `设计稿名（画板尺寸）｜version=88e0aaa6｜更新于 2026-09-17`。**拿不到就不打**；读旧版时会写成「最新版更新于 …（你读的是旧版）」，不把最新版的时间当成这版的时间。`read_blocks` 的返回里另有**同源**的结构化 `version`（`id` / `isLatest` / `latestAt` / `count`）—— 与标题行共用同一份 meta，不会两处各算一遍。 |
| **「对比度（无障碍）」** | `read_blocks` 末尾（「间距一览」之后） | 每个文本层的**文字色 vs 有效背景色**的 WCAG 对比度：正文 ≥4.5:1、大号（≥24px，或 ≥18.66px 且 bold）≥3:1。**只列不达标**的，并给**可直接改的色值**（如「文字色压暗到 `#767676` 或更深」）；全达标时给一句「全部达标（最低 x.xx:1）」，不静默。背景取法：沿**祖先链**找最近的带 fill 的层 → 缺则落**画板底色**，半透明**逐层合成**（不是当实色算）；两者都没有就单独列进「背景无法确定」并**明说不判断**（绝不当白底算）。同一对色值换个字号结论就不同（阈值真的用了稿里的字号/字重）。**零额外网络请求**。 |
| **「评论」** | `read_blocks` 末尾（「对比度」之后、尾注之前） | 稿上**人类留的评论 / 标注**（「要个png的图片」这种话只在评论里，图层树里**没有**）逐条列出：内容 + 谁说的 + 哪个版本 + 未读标记 + **映射到落在哪个块**（`position_x/y` 是**归一化 0~1**，已按画板尺寸换算后再匹配；命中不了就**明说"未落在任何块上"**，最多附一句"最近的是…"当线索，**不硬套**）。**有评论才加标题行那句提醒**，没有就一个字都不加。⚠️ 评论是**独立接口** → `read_blocks` 因此从 2 次请求变 3 次，传 `comments:false` 可跳过。详见 [评论.md](评论.md)。 |
| **结果尾注** | 各渲染末尾 | `— ≈4.30KB；本稿 43 层；本次列了 6 个容器 / 8 个文本层` + 一行「下一步该用什么」。有体积概念，才不会动辄去全文读落盘的 JSON。 |
| **`切图` 标记** | `summary` 的关键容器「填充」列 | 切图块（如头像）**天然没有填充也没有圆角**，以前会被关键容器过滤掉；现在放行并标 `切图`。要拿素材用 `download_slices`。 |

> 另有**注入内容**（`SYSTEM_HINT`）把"什么时候用哪个工具"直接写进了系统提示：
> 还原布局用 `read_blocks`、按区域取数用 `region`、**别**"summary 不够就转 full 再自己写脚本解析"。
> 全文见 `lib/index.js` 的 `SYSTEM_HINT`。
