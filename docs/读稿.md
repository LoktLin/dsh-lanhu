# 读稿：三种视图与关键列

> 返回 [README](../README.md) ｜ 完整参数见 README 的「工具」一节。

## 读稿：三种视图

| 视图 | 用途 | 一句话 |
|---|---|---|
| **块级清单** `blocks` | 还原时最常看 | 几百个图层 → 一百多个「块」，每块带齐属性，还单独列出**分割线** |
| **区域表** `region` | 抠某个区块的图层（替代手写抠图脚本） | 内边距已按父子坐标算好；可加 `limit` 看全量 |
| **全量** `format=full` | 落盘 JSON，程序化消费 | 扁平数组，字段见下 |

### 三张表里"最容易漏"的列

数据层一直有、但以前**不打出来就等于不存在**的几项，现在都在表里：

| 列 | 含义 | 为什么要看 |
|---|---|---|
| **不透明** | 图层 `opacity`，**已累乘祖先链** | 半透明的"厚度层 / 底纹"漏读会被做成生硬实心块。注意它和填充色 `@xx%`（**填充 alpha**）是**两回事**，两者独立叠加 |
| **字体** | `font.family` 短名 | 一个封面用 3 种字体是常态；漏读就全站一个字体 |
| **行高·字距** | 形如 `22/0.5` | 排版还原的关键，缺失只能靠猜 |
| **底色/填充** | 多段渐变串成 `#a@18%→#b@10%`；只有描边的层标 `描边 #xxxxxx` | 渐变只打第一个 stop 是**最隐蔽**的坑：表格里"有颜色"，看着不缺信息 |

> 实测：某 1920×1080 大屏稿（711 层）全稿 **55 层多段渐变**、**48 层半透明** —— 不扫这两类直接开工会返工。

### 坐标映射（把设计稿坐标搬进你的坐标系）

```bash
lanhu read --project <pid> --image <iid> --region 170,680 \
  --map-box "659.32,120.58,1271.64,651.53" \   # 设计稿参照框
  --to-box  "4,4,442.3,480.3"                  # 目标参照框（如你的 SVG viewBox）
```

输出多两列「映射 x,y / 映射 w×h」。**x/y 各自独立缩放（非等比）** —— 两个坐标系长宽比不同也能对上。

## 接稿时的三条核对

1. **接稿先扫三列**：「不透明」「字体」「行高·字距」，再确认渐变是完整的（带 `→`）——
   这两分钟能挡掉一整类"做出来才发现"的错误：半透明厚度层被做成实心、全站变成一个字体、多段渐变被压成纯色。
2. **核对"这个图层到底有没有切图"**：设计稿里是矢量的图层（`hasImage=false`）蓝湖**不会导出切图**，
   随便找个图标顶上，风格一眼就不对。
3. **间距取值拿相邻块的坐标相减**，不要凭感觉写百分比；并且内部间隙要小于列间隙，别把关系写反。

## 切图密度：机制在，但**实测配不上**（别指望它给数值）

`lanhu_download_slices` 的 `mapping.json` 里每张图带 `density.effectiveDensity`（实际像素 ÷ 渲染尺寸）
与 `resolutionLimited`（是否低于目标倍率），并在不合格时**直接打印警告**。
目标倍率默认取设计稿自带的 `meta.sliceScale`（实测某稿是 4）。

**但实测这份稿 12 张切图配到 0 张**，两个原因：

| 现象 | 实测数据 |
|---|---|
| 素材带额外留白 | 图层 `48×56`×4 应为 `192×224`，实际素材是 **`200×244`** |
| 同尺寸图层重复 | 4 个 `20×20` 图层都对应 `80×80`，按「唯一才认」必须拒绝 |

根因在数据侧：竞品算得出密度是因为它的通道带 `asset.render_bounds`；
**我们这条通道的 `tree.assets` 是裸 URL 数组**，既没有渲染边界，也没有与图层 id 的对应关系。

所以当前行为是：**`effectiveDensity` 为 `null` + `matchReason` 写明原因**（
`ambiguous` / `no-layer-match` / `slice-scale-unavailable`），**宁可不给，也不给一个错的密度**。

> 因此「切图够不够清晰」这件事，目前仍然只能靠：**看 `f.width/height` 与图层尺寸自己判断**，
> 或让设计师重导。判读时注意 **`null` 与 `[]` 的区别**：
> `densityLimited: null` = **一张都没能评估**（本通道的 `tree.assets` 是裸 URL，没有 `render_bounds`，实测 12/12 都配不上）；
> `densityLimited: []` = 评估过了且**都达标**。把 `null` 读成"达标"就是反的。
