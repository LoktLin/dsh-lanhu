# 生成代码（`lanhu_gen_code`）—— 可直接粘贴的 CSS / WXSS

给一张稿（或某个区域 / 某几类块）→ 产出**能整段复制进文件**的样式代码。

与读稿的分工：

| 你想要的 | 用哪个 | 出口形态 |
|---|---|---|
| 「**设计稿是什么**」——人一眼核对 | `lanhu_read_blocks` | 表格 |
| 「**我该往文件里写什么**」——照着实现 | **`lanhu_gen_code`** | **代码块** |

```
lanhu_gen_code {"url": "<蓝湖链接>", "target": "both"}
lanhu_gen_code {"url": "…", "region": "700,1000"}        # 只看某一段
lanhu_gen_code {"url": "…", "kind": "text,pill"}         # 只要某几类块
```

**只读**：从不写任何东西（只调用既有读稿接口）。多账号自动判定、版本可溯源，与读稿同一套。

---

## 1. 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `url` / `projectId` + `imageId` | — | 贴整条蓝湖链接最省事（自动解析 `tid/pid/image_id`） |
| `target` | `both` | `web` = px（1:1）；`mini` = rpx；`both` = 两套各成一段 |
| `region` | — | 只生成某区域：`"y0,y1"` 或 `"x0,y0,x1,y1"` |
| `kind` | — | 只生成某几类块：`card,container,pill,text,image,divider` |
| `minWidth` | — | 只要宽度 ≥ 该值的块 |
| `limit` | 60 | 最多生成几块（大屏稿几百块，全吐出来没人粘得完） |
| `includeNoise` | `false` | 是否连系统 UI / 图形碎片一起生成（与读稿同一个折叠口径） |
| `version` | latest | 复现"当初那一版"时传它；给不存在的 id 会报错，**不静默回退** |

被截断时返回 `truncated: true`；返回体里还有机器可读的逐块属性行（`codes[]`），
与 `text` 是**同一次生成**，不会各算一遍。

---

## 2. 双平台（换算只有一套实现）

`rpx = px × 750 ÷ 画板宽`：

| 画板宽 | 比例 | 例 |
|---|---|---|
| 375 | ×2 | `width: 311px` → `width: 622rpx` |
| 750 | ×1 | `width: 311px` → `width: 311rpx` |
| 1920（大屏 / Web 稿） | ×0.39 | `width: 99.47px` → `width: 39rpx` |

换算走既有的 `toTarget(px, 'mini', …)`（验收那条链用的同一份），**没有第二套实现**。

⚠️ **画板宽度拿不到时只给 px**（返回体 `miniAvailable: false`），
**不拿 375 兜底硬算** —— 那正是"基准用错"最典型的来源。输出段落标题里也会写明本次用的基准。

## 3. 输出长什么样

```css
/* CSS + WXSS —— 小程序（375×812） ｜version=xxxx｜更新于 2026-… */
/* 共 21 块 ｜ 按画板宽 375（基准 750）→ **×2** */

/* ═══════════ Web（px，1:1） ═══════════ */

/*  2. Button · 311×42 · 卡片 */
.button {
  width: 311px;
  height: 42px;
  background: linear-gradient(90deg, #6f67f9 0%, #5446f3 100%);
  box-shadow: inset 0px 4px 12px 0px rgba(232, 230, 255, 0.35), 0px 4px 10px 0px rgba(0, 0, 0, 0.12);
  border-radius: 9999px 9999px 9999px 9999px;
}

/* ═══════════ 小程序（rpx）— 按画板宽 375（基准 750）→ **×2** ═══════════ */

.button {
  width: 622rpx;
  height: 84rpx;
  background: linear-gradient(90deg, #6f67f9 0%, #5446f3 100%);
  box-shadow: inset 0rpx 8rpx 24rpx 0rpx rgba(232, 230, 255, 0.35), 0rpx 8rpx 20rpx 0rpx rgba(0, 0, 0, 0.12);
  border-radius: 19998rpx 19998rpx 19998rpx 19998rpx;
}
```

覆盖：尺寸 / 背景（纯色 + 多段渐变，**含角度、全部 stop、小数百分比、rgba 与 hex 混用**）/
`opacity`（图层不透明度，与填充色 alpha 是两回事，两个都出）/ `box-shadow`（多层、`inset`、`spread`、
hex 阴影色）/ `text-shadow` / **四值** `border-radius` / 边框（实色 → `border`；**渐变 → `border-image`**）/
`backdrop-filter`（背景模糊）/ `filter` / 字体族·字重·字号·色·行高·字距·对齐 /
`transform: rotate()` / **富文本 `<span>` 分段**。

**数据里没有的属性一个字都不出**（没有 `line-height` 就不写 `line-height`）；
**有数据而值为 0 要出**（有全 0 圆角数据 → `border-radius: 0px 0px 0px 0px`）。
两者不是一回事，"有 0"和"没这个字段"必须分开对待。

## 4. ⭐ 与蓝湖「代码」面板的已知写法差异

两者都是**合法 CSS**，我们沿用自己那套（口径一致比模仿模板重要）：

| 项 | 蓝湖「代码」面板 | 我们 | 为什么 |
|---|---|---|---|
| 圆角 | 四角相等时写单值（`22px`），全 0 却写四值（`0px 0px 0px 0px`）——**它自己不一致** | **一律四值**（`22px 22px 22px 22px`） | 一致性；四值还能表达非对称 |
| 半透明色 | 逗号后无空格 | `rgba(87, 74, 244, 0.1)`（**逗号后有空格**） | 全项目唯一出口 `rgbaString()`，改它必须一处生效 |
| 颜色大小写 | 大写 `#6F67F9` | 小写 `#6f67f9` | `rgbHex()` 的输出形态（读稿输出同一套） |
| 不透明渐变 stop | 也写 `rgba(55, 109, 202, 1)` | 写 `#376dca` | 不透明就用 hex |
| `font-family` | 不加引号，且会把 `Alibaba PuHuiTi 2.0` 写成 `Alibaba PuHuiTi 20` | 含非标识符字符时**加引号**（`"Alibaba PuHuiTi 2.0"`）；纯标识符序列不加 | 不加引号时带 `.` 的名字不合法 |
| `font-family` 重复 | 同一个族写两遍 | 写一遍 | — |
| `font-weight` | 正文写 `normal` | 写数值（`400`） | 稿里就是数值；`normal`/`bold` 是它的模板怪癖 |
| `font-style` / `text-transform` | 总是写 `normal` / `none` | 同（总是写） | 文本块的默认值，写出来等价且完整 |
| 渐变 stop 位置 | 0% / 100% 时省略 | **总是写** | 位置是信息，不省 |
| 渐变角度 0° | 写 `360deg` | 写 `0deg` | 等价；统一规范化到 `[0,360)` |
| 旋转 | **不给**（代码面板没有这一项） | 给 `transform: rotate(Ndeg)` | 标注面板里有（`旋转 180°`）—— 数据里有就不该丢 |

## 5. ⭐ 照抄蓝湖会**画错**的三处（这几处我们有意不同）

| 场景 | 蓝湖给 | 我们给 | 照抄的后果 |
|---|---|---|---|
| **椭圆图元**（`paths[0].type === 'ellipse'`） | `border-radius: 0px 0px 0px 0px` | `border-radius: 50% 50% 50% 50%` | 圆形环会画成**方形环**（圆的形状来自矢量路径，不是圆角） |
| **渐变文字**（文字层 + 填充是渐变 + **没有** `color`） | 只给 `background: linear-gradient(…)` | 那个 `background` + `-webkit-background-clip: text` + `background-clip: text` + `-webkit-text-fill-color: transparent` + `color: transparent` | 渐变色会画成**文字背后的一个矩形色块** |
| **渐变描边** | `border: 1px solid;` + `border-image: … 1 1` | 同 | （这一处蓝湖是对的；要记的是**实色分割线不要用 `border-image`** —— 两条路必须分开） |

> 本项目给 AI 的提示里写着「`divider` 还原用 1px 实线，**别用 border-image**」——
> 那条**只对实色分割线成立**。渐变描边在 CSS 里**只有** `border-image` 这条路。

## 6. 精度：alpha **不取整**

```
rgba(255, 255, 255, 0.02)   ← 极淡的边框/描边；取整到 1 位小数就变成 0 = 边框直接消失
rgba(255, 255, 255, 0.1)
rgba(0, 128, 229, 0)        ← alpha 恰好 0（完全透明），本来就该是 0
```

- **alpha 一律保留原值**（到 2 位小数），既**不**统一取到 1 位，也**不**为"好看"抹掉小值；
- `0.02`（要出）与 `0`（本来就透明）**是两回事**，不许混为一谈；
- 渐变 stop 的**位置**同样不取整：它是 `0..1` 的归一化值，压到 2 位小数就等于把百分比精度砍到 1 位
  （实测参考里那段就是 `29.66%`，取整会变成 `30%`）。

这类错**输出完全合法、只是数值被抹平**，靠肉眼看不出来 —— 所以有专门的断言与变异守着。

## 7. 富文本（一段文字里多种样式）

稿里 `text.styles[]` 是**按 run** 给的（每段有自己的字体 / 字号 / 字重 / 颜色）。
我们给：主样式写进块规则，**与主样式不同的 run** 各给一条差异规则 + 一行 HTML 蓝图：

```css
/*  18. 值 / 计量器具与表号 · 327×20 · 文本 */
.值-计量器具与表号 {
  width: 327px;
  height: 20px;
  font-family: "Alibaba PuHuiTi 2.0";
  font-weight: 500;
  font-size: 12px;
  color: #f3faff;
  line-height: 18px;
  text-align: left;
  font-style: normal;
  text-transform: none;
}
/* 富文本：该层有 4 段样式（蓝湖的 web 输出会压扁成一段，我们给分段） */
/*   1号车间电能表 · <span class="r1">表号</span> <span class="r2">MTR-001</span> */
.值-计量器具与表号 .r1 { color: #8fa9c1; }
.值-计量器具与表号 .r2 { font-weight: 700; color: #70e8ff; }
```

蓝湖自己的 **web** 输出在这条上是**压扁**的（只给主样式，两段差异在 CSS 里没有任何体现）——
所以这里我们比它多一步，不是"与它不一致"。

## 8. 不支持 / 已知缺口

| 项 | 现状 |
|---|---|
| **径向渐变 / 角度渐变** | 只支持线性渐变（蓝湖数据里也是 `type: 0` 线性） |
| **图层镜像**（变换矩阵行列式为负） | 只还原旋转，**不还原镜像**（`scaleX(-1)`）；这类层在稿里占比不高，遇到要人工看 |
| **旋转图层的尺寸/位置** | 给的是**旋转后的包围盒** + `rotate(Ndeg)`，没有还原 `transform-origin` —— 简单矩形/图标够用，复杂组合要人工调 |
| **一个图层多条边框** | 只取第一条（既有 `borderOf()` 的口径，与读稿一致） |
| **阴影的 `blendMode`** | 不还原（CSS 没有等价物） |
| **描边对齐方式**（`lineAlignment` 内/中/外） | 不还原；CSS 的 `border` 恒为内描边 |
| **Sketch 插件格式的文字 runs** | **未实测**（Figma 侧已实测）。若该格式也有 `text.styles[]` 会自动生效，否则会被当成单一样式 |
| **Sketch 插件格式的旋转** | **未实测**：该格式归一化后的节点上**没有** `rotation` 字段（我们没采），所以这类稿不会出 `transform` —— 要用得先把该字段采进富信息 |

## 9. 未验证 / 不确定（如实列出）

1. **旋转的方向**：我们照抄数据里的 `rotation` 值直接给 `rotate(Ndeg)`。
   实测样本只有 **180°**（无方向性）。若发现方向反了，改动点是**一处**
   （`blockCssLines` 里的 `transform` 那行加负号即可）。
2. **渐变角度是否要乘图层宽高**：实测校准过 3 个真实样本（90° / 55° / 0°）全部吻合；
   但**没有**"非轴对齐 × 非正方形"的样本可用来区分两种算法（正方形与轴对齐两者同值），
   所以按"用归一化坐标、不乘宽高"实现（这也是蓝湖给出整数的唯一自洽解释）。
3. **参考 ⑧ / ⑨ / ⑩ 那条（464×396 卡片 / 112×44 发光按钮 / 120×90 毛玻璃）**：
   没能在两个候选项目里定位到对应稿，**未做真机对照**；它们的数值形状
   （3 stop + 小数百分比 + `opacity` / hex 阴影色 + `spread` / `backdrop-filter`）
   已由离线断言覆盖。
4. **Sketch 插件格式**的旋转与文字 runs：未找到可读的该格式稿，未实测。

## 10. 自检与变异

```bash
node test/selfcheck.mjs        # 含「⑯ 生成代码」一组
node test/readme-test.mjs
```

「⑯」组覆盖：双平台换算互相印证（375→×2 / 750→×1 / 画板宽未知→只给 px）、四值圆角（全等与全 0）、
多层阴影含 `inset`、hex 阴影色、`text-shadow`、`backdrop-filter`、`opacity`、
渐变（角度 + 全部 stop + 小数百分比 + rgba/hex 混用）、渐变边框 → `border-image`、
字体族引号规则、`line-height` 只在有值时出、椭圆 → `50%`、渐变文字三件套、
富文本分段、旋转、class 命名与去重、**只读（桩 fetch 断言只发 GET）**。

变异测试（把实现改坏，看断言是否变红）覆盖 14 组：rpx 基准用错 / 圆角全等写单值 /
阴影只出第一层 / 渐变丢 stop / 自己另写 rgba 格式化 / 椭圆当矩形 / 渐变文字只出 background /
spread 写死 0 / 省掉旋转 / alpha 取到 1 位小数 / 富文本静默压扁 / 编造 line-height /
stop 位置取整 / 文字阴影走 box-shadow —— **全部变红**。
