# 侧边面板、多账号与 Cookie

> 返回 [README](../README.md) ｜ 完整参数见 README 的「工具」一节。

## 侧边面板（四个 Tab）

侧栏底部「蓝湖」入口 → 浮层。面板与工具走**同一条数据通道**（Host 的 `/lanhu/*` 路由，仅本机可访问）。
`Esc` 或右上角 × 关闭；面板内容区是唯一滚动容器。

标题栏显示**当前版本**（读的是插件自身的 `package.json`）。npm 上若有更新，版本号右侧多一个小圆点，
鼠标停上去提示「npm 上已有新版本」——**不显示最新版本号**，也不弹任何东西。
查询结果在 Host 侧缓存（命中缓存 8 小时；查不到时 5 分钟内不重试），且**拿不到 npm 数据就只显示当前版本**：
不报错、不占位、不影响登录态检测。

| Tab | 干什么 |
|---|---|
| **块级** | 贴链接就出块级清单；类型筛选、关键词过滤、点行展开、单边边框（分割线）速查 |
| **账号** | Cookie 来源 / 打码串 / **有效期** / 团队列表；粘贴 `Copy as cURL` 更新 |
| **记录** | 每次工具调用与面板读取的时间 / 工具名 / 耗时 / 结果摘要（内存 300 条 + 落盘 `usage.jsonl`） |
| **体检** | 两个**项目级**长任务：变更（同一张稿两个版本 diff）与一致性（跨稿审计）—— 不用记命令，也能看到进度、取消、复制报告 |

## 「体检」Tab：变更 + 一致性

两个功能都不用敲命令，但**都是长任务**，所以面板先把三件事说清楚：**要花多少、跑到哪了、结论能不能信**。

```
┌ 目标项目 ─────────────────────────────────────────┐
│ [项目 ▾ 全咨2.0手机项目]（来自账号索引，不额外发请求） │
│ [或贴一条蓝湖链接………………]  [用链接定位]              │
├ 变更（设计变更 diff）─────────────────────────────┤
│ [稿 ▾ 人才详情] [读取版本]                          │
│ 起点版本（from，必填）[第 2 版 · f4fbf3f3 · 版本4 ▾] │
│ 终点版本（to，默认最新）[最新 · 97dd4840 ▾]          │
│ [对比两个版本] [取消] □含碎片                       │
│ ⏳ 正在读两个版本的图层树、逐块比对（已用 12s）…      │
│ 变化 1 块 · 新增 0 · 删除 0 · 未变 130               │
│ 结构：2 处 / 人才证书 · 类型 图片→卡片               │
│ [复制报告] [看原文] 纯文本，可直接喂 AI               │
├ 一致性（跨稿审计）────────────────────────────────┤
│ 扫描张数（默认 20）[20]  成本 = 张数 × 2 次请求，     │
│                          本次约 40 次；硬上限 200     │
│ [开始审计] [取消] □含碎片                            │
│ 扫描 3/10 张（被上限截断） · 读到图层 3 张 · 块 929   │
│ 同一组件、多种规格  [漂移] …                         │
└──────────────────────────────────────────────────┘
```

| 面板上的东西 | 为什么这么做 |
|---|---|
| **目标项目**下拉来自账号索引（首次打开面板就拉过 `/lanhu/accounts`），**不额外发请求** | 选项目不该花一次蓝湖请求；索引为空时明确提示「去账号 Tab 重建索引」，并给一条贴链接的兜底路径 |
| **扫描张数默认 20**，并在**按钮上方算出**「本次约 N 次请求」 | 工具默认 50、硬上限 200；面板是"顺手点一下"的场景，默认值不许悄悄跑几分钟。成本摆在落手之前 |
| 客户端与 Host **各夹一次**（输 `0` / `5000` 都夹到 `[1,200]`） | 不把"用户自觉"当安全阀 |
| 跑起来：**按钮禁用 + 一句话进度**（含已用秒数、扫多少张） | 这两个功能可能跑十几秒到几分钟。没有运行中状态，用户只会以为卡死然后刷新 |
| **取消** | 面板立刻回到可点状态、这次的结果作废；**Host 那一次请求会自然跑完**（蓝湖请求本身不支持中断）—— 真正的成本闸门是上面的「扫描张数」，不是取消 |
| 20 分钟没回来就按失败显示（原话写明"面板已放弃等待"） | 不静默挂着 |
| **⚠️ 匹配不可靠 / ⚠️ 判不可靠 横幅**（`role="alert"`，排在结果区**上面**） | 后端在不可靠时**故意不出明细**。这条结论必须在界面上顶出来 —— 埋在长文本里会被当成"没有变化" |
| **复制报告** + **看原文**（只读、可手选的纯文本区） | 结果是要拿去喂 AI 的；剪贴板不可用（沙箱/隐私模式）时还有手选这条路 |

失败与降级都只显示在对应区块里（❌ + 原话 + 下一步），**面板绝不 throw**：Client 半边抛错会让整个 Web 壳起不来。

> ⚠️ 观感未在真实浏览器里核过：本步只做了「最小 React 替身离屏真渲染」的结构核对 + 真机路由/CLI 的数据核对。

## 多账号（一个人多个公司 / 多套 Cookie）

**核心洞察：蓝湖链接里的 `tid` 就是团队 id，而一个团队只属于一个账号。**
所以只要每个账号存一份 `listTeams` 的结果，之后**看链接就能零请求定位该用哪个账号**（实测 2–45 ms）。

```bash
node lanhu.mjs accounts --add --alias acme --company "Acme" --clipboard  # 贴 Cookie，自动建索引
node lanhu.mjs who --url "<蓝湖链接>"                                     # 判归属（零请求优先）
```

**所有工具都带一个可选的 `account` 参数**，不给就自动按链接 `tid` 判定。结果末尾会写明用了哪个、怎么定出来的：

```
— 账号：another（自动判定 · index:teams）
```

### ⚠️ 蓝湖的权限边界（实测结论）

| 接口 | 是否按账号隔离 |
|---|---|
| `listTeams` / `listProjects` / `search` | ✅ 是 |
| **`imageDetail` / `listImages`（读稿）** | ❌ **不是** —— A 的 Cookie 能读到 B 团队下的稿 |

**这推翻了一种想当然的归属判定法**：早期实现会在"试读成功"时把稿子回填进索引并声称归属 —— 那是错的，会污染索引。
现在归属判定**只用索引**（`tid` → `pid`），未命中时只做存在性确认，**不声称归属**。

> 好消息：**账号选错不会读出错的数据**（同一张稿任何账号读到的都一样），影响只体现在**列表/搜索**这类按账号隔离的接口。

**空壳语义**：蓝湖对读不到的稿子**不报错**，而是静默返回 `{ imageId, d2cUrl: null, versionLayoutData: null }`。
判定"能不能读"必须看**有没有真实数据**，不是看有没有抛错。
