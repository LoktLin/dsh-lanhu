# 原型（Axure）页面的样式 —— 没有设计稿时的唯一依据

> **什么时候用**：项目里**一张设计稿都没有**、只有 Axure 原型时。
> 先用 [docs/产品文档.md](产品文档.md)（或 `lanhu_list_designs`）确认：
> 如果 `lanhu_list_designs` 返回 **0 张**，那 `lanhu_read_design` / `lanhu_read_blocks` **一点数据都拿不到** ——
> 这时唯一能照着实现的东西就是原型页面里的样式。
>
> **怎么用**：`lanhu_read_product_doc {"url":"<原型链接>", "format":"layers", "pageId":"<页 id>"}`
> （CLI：`node lanhu.mjs product-doc --url "<原型链接>" --format layers --page-id <id>`）

## 标题里的「路径：」是什么意思

原型页面的"名字"其实是**它在页面树里的路径**（`A / B / C` 逐级拼起来的）。
直接打印会被读成"**把多页合并了**"（实测有人据此误报过一次），所以**凡是打印页面路径的地方都带「路径：」前缀**：

```
# 原型页面样式 —— 某数据大屏
> 路径：首页（默认视觉） / 首页（贸易流向视觉） / …（pageId b6da…）     ← 标题行
## 路径：首页（默认视觉） / 首页（贸易流向视觉） / …（pageId b6da…）     ← 每个页面标题
# 块级清单 — 路径：首页（默认视觉） / …（1928×2961.91）                ← 该页的块级表
```

判定在**源头**：原型页把 `path` 当 `name` 时同时给 `nameIsPath: true`，
所有标题一律走 `titleName(meta)` —— **新增打印点必须走它**，否则又会漏一处
（曾漏过 `# 块级清单 —` 那条）。机器读的输出里也有 `nameIsPath` 字段可判断。

## 一句话结论

原型页面的 `data.js` 里**样式数据是完整的**（实测一份 861 KB / 439 个控件），
把它规范成**与设计稿同形状的图层**之后，输出与 `lanhu_read_blocks` **是同一张表** —— 不用学第二套。

## 能拿到什么（实测）

| 项 | 实测值 |

| 带底色 | 79 个（**有可见填充**的） |
| 带字号 | 250 个（⚠️ 另有 85 个文本层**导出里就没有字号**，见下第 2 条） |
| 带文本 | 316 个（文本从**页面 HTML** 取，见下第 1 条） |
| 收敛成块 | **337 块**：图片 197 / 文本 113 / 容器 26（另有系统碎片默认折叠） |
| 色板 | `#333333×239 #ffffff×186 #2aafea×161 #e79336×149 #8c8c8c×92 #ffffff@80%×53 #000b17×52 #f2f2f2×47` |
| 字号 | `13×118 12×48 16×39 14×10 20×10 36×8 28×5 48×5` |

### 计数口径（对账时看这条）

> 本插件**遍历三种子层容器**，缺一种就会静默漏层 —— 实测漏最多的一次是 41 层：

| 桶（**互不重叠**，相加即总数） | 是什么 | 实测层数 |
|---|---|---|
| ① 常规子层 | 顶层 `objects[]` + 其下递归的 `objs[]` | 439 |
| ② 状态内子层 | 动态面板**各状态里的控件**（`diagrams[].objects[]`） | 179 |
| ③ **状态容器自己** | `Axure:PanelDiagram` 节点（各带自己的背景色；**几何取自面板**，见下） | **11** |
| ④ `objects[]` 子层 | **中继器**（`repeater` 模板）1 + **表格**（`table` 单元格）40 | **41** |
| **合计（不含画板）** | ①+②+③+④ | **670** |

> ②③④ 三桶都带标记：②③ 有 `panelState`/`panelOf`，③④ 有 `containerKind`（`panel-state` / `中继器` / `表格`）。
> **改这一版前 ③ 和 ④ 是被漏掉的**（少 11 + 41 = 52 层）—— 与独立计数的差正好是这 52。

#### 这条口径**有机器守着**（不是靠人记住）

漏掉 ③④ 是同一个病：**"子层挂在哪个键上"是靠人看出来的**。现在每次归一化都会跑一遍**结构审计**：

- 判据是 **"数组元素看起来像控件吗"**（有 `id` 且带 `type`/`style`/`friendlyType` 之一），
  **不是键名白名单** —— 因为 Axure 会把子层放到五花八门的键上（实测出现过 `stops`/`cases`/`actions`/
  `subExprs`/`arguments`/`objectsToRotate`/`objectPath`/`firedEvents`/`adaptiveViews`/`variables`），
  按名字列白名单**必然漏**。
- 审计把"文档里真实出现的子层键"与 `AXURE_CHILD_KEYS`（遍历器声明会走的键）比对，
  **出现"文档里有、遍历器不走"的键就报出来**：进 `stats.unknownChildKeys`，并在输出里打 ❌ 警告
  （不是静默 —— 宁可让 AI 看到"清单可能不完整"）。
- 真实那份稿的审计结果：`objs` 381 / `objects` 278 / `diagrams` 11，**未走 = 0**。
- 同时守着 `type !== 'Axure:PanelDiagram'` 那个排除条件：**文档里的 PanelDiagram 数量必须等于经 `diagrams` 走到的数量**
  （实测 11 == 11）—— 让它不是个没人监督的魔法常量。

**将来真遇到第四种键怎么加**：在 `normalizeAxurePage` 的 `walk` 里像 `objs`/`objects`/`diagrams` 那样走一遍新键，
把键名加进 `AXURE_CHILD_KEYS`；自检里的**通用参考遍历**（不看键名、只按"元素像不像控件"走）与遍历器输出层数必须一致，
否则会红 —— 也就是说**只加遍历器不加白名单（或反之）都会被抓出来**。

另有几个**有意排除**的节点，规则写在这里（也钉在自检里）：

| 排除对象 | 为什么**不算层** |
|---|---|
| `objectPaths` | 是 `控件id → uNNN` 的**映射表**，不是控件 |
| `page` / `page.style` | 页面级样式，已并入画板层（`sizeSource` 说明尺寸来源） |
| 状态容器**没有** `location`/`size` | 不排除，但**几何取自所属面板**并标 `geometryFromParent: true`（不假装它自己有坐标） |

每个控件上能拿到的**原始字段**（`style` 里）：

```
fill / foreGroundFill / borderFill   填充色、文字色、描边色（32 位整数）
fontName / fontSize / fontWeight / lineSpacing   字体族、字号、字重、行距
location{x,y} / size{width,height}   坐标（相对父）/ 尺寸
cornerRadius / borderWidth / linePattern        圆角 / 描边宽 / 线型
opacity                              图层透明度
fillType:'linearGradient' + stops[]  多段渐变（每个 stop 的色与 offset）
outerShadow / innerShadow            阴影
friendlyType                         形状 / 矩形 / 椭圆 / 星星 / 线段 / 组合
images                              切图引用（`images/页名/uNNN.svg`）
objs[]                               子控件（递归嵌套）
```

## 三条必须知道的边界（都是实测出来的，别踩）

### 1. 文本**不在** `data.js` 里，在页面 HTML 里

`data.js` 里控件的 `label` / `rich` **全是空**（原稿以矢量/图片导出）。
正文在页面 HTML 的 `#uNNN_text`（文本域是 `#uNNN_input`）里，而且是 **HTML 实体编码**（`&#x7EFF;` = 绿）。
桥是 `data.js` 的 `objectPaths`（`控件 id → uNNN`，实测 659 条）—— 插件已经接好，不用你操心。

> ⚠️ 只看 `data.js` 会得出「这页没内容」的**假结论** —— 这是本插件早期真踩过的坑。

### 2. **85 个文本层没有字号**（不是 bug，是导出里就没有）

316 个带文本的层里，**85 个 `fontSize` 缺席**，只有一个 `baseStyle` 哈希 ——
而那个哈希在整个 `data.js` 里**从不当对象键**（文档里根本没有样式表）：
Axure 把基础样式留在了**原始 `.rp` 里**，导出不带。

**去外链 CSS 找过，找不到**（这条是实测，不是推测）：

- `files/<页>/styles.css` 里那 251 条 `#uNNN{font-size}` 经比对**全部**落在「本来就有字号」的控件上
  —— 说明那份 CSS 是从 `data.js` **生成**的，不带新信息；
- `data/styles.css` 只能给出 `.ax_default{13px}` 这种**通用兜底**，不是设计者填的值。

所以插件**留 `null`、渲染成 `?`**：

> **别把 `?` 读成 0，也别自己猜一个** —— 要么问设计，要么以最终设计稿为准。

### 3. 页面尺寸可能得靠包围盒算

实测 `page.style.size` 是 `{width:0,height:0}`（高度根本没给），可信的宽度在 `defaultAdaptiveView.size`。
两者都为 0 时插件**用控件包围盒兜底**，并在 `stats.sizeSource` 里写明来源：

| `sizeSource` | 含义 |
|---|---|
| `declared` | 稿子自己声明的 |
| `bbox` | 控件包围盒算出来的（上面那份就是这个） |
| `unknown` | 都没有 |

### 4. 动态面板的**状态图**也是控件 —— 但它们是**互斥**的

Axure 把动态面板每个状态的控件放在 **`diagrams[].objects[]`**（`type: "Axure:PanelDiagram"`），
**不在 `objs` 里**。实测那份稿有 **8 个面板 / 231 层**在里面（例如一个日历有 August / July / June 三个状态，各 41 层）——
**不走进来会少掉三分之一的控件**。

**状态容器自己也是一层**：实测同一面板三个状态的背景色**各不相同**
（`#ffffff@29%` / `#118281@29%` / `#ffffff@100%`），而**面板自身没有 fill** ——
只走它的 `objects` 会把「这一状态的背景」整块丢掉。

插件已经走进去，并做了三件事让调用方**不至于误解**：

- 层上带 `panelState`（状态名，如 `August`）与 `panelOf`（所属面板的控件 id）；
- 路径里带上状态：`Calendar picker / Calendar pane /（状态 August）/ …`；
- `stats.panelStateLayers` / `panelCount` 给出数量，输出里也有一条显式提醒。

> ⚠️ **它们是互斥的备选状态**（同一面板一次只显示一个），**不是同时显示的层**。
> 而且**导出里没有"当前是哪个状态"的字段**（实测找不到 `panelIndex` / `default` 之类）——
> 所以哪个状态在跑，得按业务自己判断。渲染时**不要把它们叠在一起**。

## 与设计稿的差别（**要如实告诉调用方**）

- 原型是**交互稿**：颜色/字号是设计者随手填的，**不等于最终视觉稿**。
  **有设计稿时一律以设计稿为准**（`lanhu_read_design` / `lanhu_read_blocks`）。
- 坐标：Axure 的 `location` 是**相对父容器**的，插件已逐层累加成**绝对坐标**（与设计稿那条链一致）。
  `inset`（内边距）则直接用相对坐标算 —— 比设计稿那条链更直接。
- 一个**真语义差异**（已在代码里处理）：Figma 里文字节点的 `fills` **就是文字色**，
  而 Axure 的 `fill`（背景）与 `foreGroundFill`（文字色）是**两个独立字段** ——
  所以原型层带 `fillIsBackground: true` 标记，否则「文本域那个 `#facd91@6%` 背景」会被按 Figma 规则整块抹掉。

## 验收（`lanhu_verify_blocks`）目前**没接**原型页

如实说明原因，别以为接了：

1. **没有可测的页面**：块级验收要拿一个**已实现的前端页面地址**去比对。这份原型对应的页面还不存在，
   接了就是一段**没有任何真机证据的代码** —— 本项目的铁律是"无证据不算完成"。
2. **坐标空间不同**：原型画布是 1928×2962 的**绝对坐标**、且不是响应式布局；
   被测页面有自己的盒模型与视口 —— 在缺少 `data-lanhu` 标注时，几何最近邻匹配会拿**不可比的东西**去比。

**建议的接法**（等页面真的做出来再验收时）：先用 `--format layers` 把原型页的块清单落一份当基准，
页面实现后按文本内容对齐（原型里的文本已能取到，这是最可靠的锚点），再逐块比六项属性。
