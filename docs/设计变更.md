# 设计变更 diff：这次设计改了什么

> 返回 [README](../README.md) ｜ 完整参数见 README 的「工具」一节。

## 为什么要有它

设计一改，已经写好的页面就过期了 —— 但**没人知道改了哪**。蓝湖自己不提供版本对比。
`lanhu_diff_design` 把「同一张稿的两个版本比一次」变成一次调用。

```json
{ "projectId": "...", "imageId": "...", "from": "<旧版本 id>", "to": "<新版本 id，省略=最新版>" }
```

```bash
lanhu diff --url "<蓝湖链接>" --from <旧版本 id> [--to <版本 id>] [--all]
```

版本 id 从 `lanhu_read_blocks` / `lanhu_read_design` 返回的 `version.id` 里取（标题行也会打）。CLI 不认 `--version`，它比的是**两个**版本。

## 输出长什么样

真实一次调用（375×1333 的「人才详情」，跨了 5 个版本里的最旧一版 → 最新版）：

```
设计变更：v29bb7fbb → v97dd4840（相隔 9.7 天）
· 稿：人才详情 375×1333 · 块数 131 → 131
· from：第 5/5 版 13 Sep 2026 00:51:03 UTC **不是**最新版 / to：第 1/5 版 22 Sep 2026 16:58:24 UTC 最新版
· 匹配可靠度：✅ 131 块按 path 精确匹配 · ⚠️ 0 块只能靠近似匹配 · ❌ 0 块无法匹配（匹配率 100%）

· 结构：
  - 人才证书 类型 图片→卡片
  - 人才证书 切图 有→无
· 未变：其余 130 块
注：画板的画布坐标 -9876,463→-9879,487 变了，那是稿子在 Figma 画布上的摆放位置，**不是设计变更**（块坐标本来就相对画板），已从「布局」里排除。
```

四条组织纪律：

| 纪律 | 为什么 |
|---|---|
| **分类只列有变化的**：尺寸/圆角 · 颜色 · 布局 · 文字 · 边框 · 结构 · 新增 · 删除 | 倒一堆坐标没法照着改代码 |
| **数值给「从→到」** | 只给新值看不出改了什么 |
| **未变的块只给一句汇总**（"其余 130 块"） | 逐块列未变会把真变化淹掉 |
| **没有变化时明说「两版一致」** | 静默空输出会被当成工具坏了；而"设计没改、代码可以不动"本身就是答案 |

机器可读部分同源给出：
`counts.changed.{size,color,layout,text,border,structure}`、`counts.{unchanged,added,removed}`、
`reliability.{exact,approx,unmatched,matchedRatio}`、`identical`、`reliable`、`changes.*`。

## 两块怎么算「同一块」：三级，每级都可解释

| 级 | 判据 | 标注 |
|---|---|---|
| ① 身份 | 层的 **path**（`父/子/名`）相同 | `exact` |
| ② 近似 | 类型相同 **且** 文本相同 **且** 中心点够近（默认 ≤24px，或较大边的 25%）**且** 宽高差 ≤25% | `approx` |
| ③ 配对失败 | 剩下的 | 报「新增 / 删除」 |

两个刻意的取舍：

- **几何只用来"在同一个 path 组里挑哪一个"**（同名兄弟层很多：实测 159 块 / 134 个唯一 path），
  **不参与成败判定**。块挪了 8px 仍是同一块 —— 那是"布局变化"，不是"匹配失败"。
- **改了文案又改了层名 → 报"删除 1 / 新增 1"**，不硬认。三条判据缺一条就不猜。

### 可靠度：能不能信这张差异表

| 判据（阈值都在 `LIMITS` 里，不裸写在逻辑里） | 结论 |
|---|---|
| 匹配率 < 50%（分母是**两边块数的较大值**） | 不可靠：整版重画 / 重排 / 换了命名体系 |
| 近似匹配占已匹配 > 50% | 不可靠：身份大面积对不上，全靠几何猜 |
| 块数 < 8 且**全部**靠近似 | 不可靠：小样本比例没意义，但"全靠猜"仍降级 |

**不可靠时不出明细表**，只说清楚为什么、以及下一步：

```
⚠️ **这两版差异过大，逐块对比不可靠 —— 不出明细表。**
· 只有 1/20 块能配上（匹配率 5%），19 块对不上 —— 这通常意味着设计**整版重画/重排**或换了一套图层命名。
· 已匹配 1/20（精确 1 · 近似 0）；另有 9 块只在 from 里、10 块只在 to 里。
· ⚠️ 上面这两个数**不等于"删除/新增"** —— 它们只是"没配上对"的块；谁是谁已无从判断，所以不给清单。
```

这是本功能最重要的一条纪律：**硬凑一张看起来精确的差异表，比不给更糟** —— AI 会照着错的结论去改代码。

## 已知边界（都是有意为之，不是遗漏）

| 现象 | 说明 |
|---|---|
| **画板自己的 x/y 变了不算变更** | 那是稿子在 Figma 画布上的**绝对摆放位置**（实测 `-9876,463 → -9879,487`），块坐标本来就相对画板。它不进「布局」，但会用一行"注"如实交代 —— 不静默吞掉 |
| **系统 UI / 图形碎片默认不参与比对** | 与块级清单**同一个折叠口径**（`visibleBlocks`，唯一一份实现）；尾注会写明共几块未参与，要一起比传 `includeNoise:true` |
| **`from` 必须是真实存在的版本 id** | 给不存在的 id 会**报错**（`VERSION_NOT_FOUND`，文案里列出该稿真实的版本 id），**绝不静默回退到最新版** |
| **同一版本比自己 → 报"两版一致"** | 防"永远有差异"的假阳性；它真的走一遍逐块比对，不是特判短路 |
| **网络请求恰好 3 次** | 1 次版本列表（它同时给出每版的 `json_url`）+ **2 次图层树**，不做逐版本探测 |
| **只比块级模型里的字段** | 比的是 `read_blocks` 那套块（圆角/大小/底色/文字色/字号字重字体族/行高字距/不透明度/边框/类型/切图/形状/子层数）。**切图素材本身的内容不在比对范围内**（`hasImage` 翻转会报，图换了内容不会报） |
| **`identical` 的含义是"块模型逐项无差异"** | 不是像素级 diff：一张同尺寸新切图换上去，块模型看不出来 |

## 在面板上用（不用记命令）

侧栏「蓝湖」→ **体检** Tab → 变更区：选项目 → 选稿 → 「读取版本」→ 挑起点/终点版本 → 「对比两个版本」。
起点默认**上一版**、终点默认**最新版**（不会默认成"自己跟自己比"）。结果里就是上面那张差异表，
外加「复制报告」——一键把纯文本报告拿走喂 AI。

三条与命令行同源的纪律，在面板上的表现是：

| 纪律 | 面板上的样子 |
|---|---|
| 不可靠时不出明细 | 结果区**上方**一条 ⚠️ 横幅（`role="alert"`）：明说"匹配不可靠 + 所以不列逐块差异明细"，并给出精确/近似/对不上/匹配率四个数。横幅**排在结果数字之前**，不会被人当成"没有变化" |
| 长任务要有反馈 | 跑起来按钮变「对比中…」并禁用，下面一行 `⏳ 正在读两个版本的图层树、逐块比对（已用 12s）…`；另有「取消」 |
| 取消的语义要诚实 | 「取消」= 面板不再等、这次结果作废（Host 晚到的回包不会把结果贴回来）；**Host 那一次请求会自然跑完**，所以别拿它当省额度的手段 |

## 改了前端之后

- 逐块对页面验收 → `lanhu_verify_blocks`（四态报告 + 可直接抄的改法）。
- 想知道"我这一版代码对应的是哪一版稿" → 读稿返回里的 `version`（含 `id` / `isLatest` / `latestAt` / `count`）。
