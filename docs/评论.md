# 评论 / 标注：读「人类留在稿子上的话」

> 返回 [README](../README.md) ｜ 读稿的三种视图与列含义见 [读稿.md](读稿.md)。

设计稿的图层树回答的是「**稿子长什么样**」，回答不了「**人类要求改成什么样**」。
而「要个png的图片」这种话**只存在于评论里** —— 图层树里一个字都找不到。

这个能力解决的就是这一句：把**评论/标注**读回来，并且**映射回它落在哪个块**，
让 AI 直接知道"该改哪儿"，而不是只知道"有人说过话"。

---

## 接口与纪律（实测，别再摸一遍）

评论**不在图层树里**，是**独立接口**：

```
GET https://lanhuapp.com/api/project/comment?page=1&pageSize=20&image_id=<imageId>
→ { "has_comment": true, "has_next": false, "total": 1,
    "result": [ { "id": …, "content": "要个png的图片", "content_rich_text": …,
                  "position_x": 0.3217459008974022, "position_y": 0.2596585570581626,
                  "read": false, "replies": [], "create_time": 1791587876,
                  "user": { "name": "qzdesign01", "nickname": "管理", … },
                  "version": { "version_id": "88e0aaa6-…", "version_info": "版本2" } } ] }
```

三条硬事实（都是踩出来的）：

| 事实 | 说明 |
|---|---|
| **必须给 `image_id`** | 只给 `project_id` 会报 `{"code":"10007","msg":"Project not exist"}` —— 这条接口认的是稿，不是项目 |
| `position_x/y` 是**归一化 0~1** | 而块的 `x/y/w/h` 是**画板相对 px**。两套坐标系直接比**不会报错**，只会静默地"一个块都不命中"（这里差一个画板宽） |
| **只读** | 本插件只发 GET，**从不**改 / 删评论，也**不标记已读**。`read` 字段只读不写 |

## 输出长什么样

有评论时，`lanhu_read_blocks` 的**标题行**会给一句提醒，末尾（「对比度」之后、尾注之前）多一段「评论」：

```text
# 块级清单 — 人才弹窗（375×812） ｜version=88e0aaa6｜更新于 2026-09-17 ｜本稿有 1 条评论（含未读 1）

## 评论（1 条，含未读 1）
> 来源：蓝湖的**评论 / 标注**（独立接口，**不在图层树里**）—— 人类留的需求就写在这儿（如「要个png的图片」）。
> 落点：接口给的是**归一化 0~1** 坐标 `position_x/y`，这里已按画板 375×812 换算成稿上坐标再匹配块（**别自己再乘一遍**）；匹配不上就**明说**，不硬套。
> 只读：本插件只发 GET，从不改 / 删评论，也不标记已读。

- 评论（@管理（qzdesign01） · 版本2 · **未读**）：「要个png的图片」
  - ↳ 挂在 **Section - ModalDialogCard** 这块（卡片 · 343×458），落点 (120.65, 210.84)
  - ↳ 该块内最细的层：**生成男士职业照 1**（shapeLayer · 120×152）—— 要精确到元素时看它
```

**没有评论时，标题行与正文一个字都不加** —— 逐字节与以前一致（有断言钉住）。

## 落点映射：怎么定的

1. **换坐标**：`归一化 × 画板宽高` → 稿上坐标（唯一出口是 `commentPoint`，别在别处再乘一遍）。
   `(0,0)` 是蓝湖"没定位在这张稿上"的**哨兵值**，不当地址用（否则每条没定位的评论都会命中左上角那个块）。
2. **候选块**：**全稿可见块**去掉画板 —— 画板（`depth 0`）的坐标是**画布绝对坐标**（实测 `-12638` 这种），拿它当容器会命中一切。
   候选**不受 `region` / `kind` / `minWidth` 影响**：评论是整张稿的标注，不该因为"你这次只看某个区域"就变成"没落在任何块上"。
3. **落在多个块里** → 取**面积最小**的（最具体）；
   面积**几乎相同**的候选（面积落在 `[最小, 最小 ÷ commentsSameBoxRatio]` 区间内，如卡片与它的 `X:shadow` 副本实测只差 0.02% 面积）取**层级更浅**的那个（元素本体，不是装饰副本）。
4. **一个块都没命中** → **如实说「未落在任何块上」**；只有最近的块在 `commentsNearDistance` 内，才附一句"最近的是…（约 Npx 外）"当线索，并**明说那不是命中**。
   不硬套一个块 —— 拿不准就明说，是本项目的铁律。
5. **最细层线索**（可选，只在能给出真名字时给）：块里命中的**面积最小、且有真名字**的图层。
   有些真元素不成块（无填充 / 无边框 / 无圆角 / 非切图 → 判成 `other` 不进块模型），例如上例的职业照占位层 ——
   只给块会停在"某张卡片"，给到最细层才正对评论说的东西。工具默认名（`Vector` / `Group 1321314767`）**一律不认**（复用审计那一把尺子 `isAutoLayerName`）。

## 成本与开关

| | 默认 | 说明 |
|---|---|---|
| 工具 `lanhu_read_blocks` | **读** | 评论是"人话需求"的唯一来源，读稿时默认带回来 |
| 工具参数 `comments: false` | — | **跳过这次请求** |
| CLI `lanhu blocks` | **不读** | 要读得显式加 `--comments`（既有 CLI 输出因此**逐字节不变**） |
| `lanhu_verify_blocks` / 面板 `/lanhu/preview` | **不读** | 它们不展示评论，不发那次请求（行为与以前完全一致） |

⚠️ **成本**：评论是**独立接口** → `read_blocks` 从 **2 次请求变成 3 次**（分页时每页 +1）。
上限（都在 `LIMITS` 里，不在逻辑里裸写）：每页 `commentsPageSize` 条 × 最多 `commentsMaxPages` 页，
撞上限返回 `truncated: true` **并在文本里写明**（不静默截断）。

## 失败怎么处理（**明说，不静默**）

评论接口挂了 **绝不让 `read_blocks` 失败**：块表 / 边框 / 间距一览 / 对比度 / 尾注**照常**（有断言：把失败那段摘掉 == 完全不读评论的那份文本）。

```text
## 评论（**读取失败**）
> 评论接口这次没读通 —— **这不代表"没人留评论"**，别当成"设计师没留言"就往下做。
> 失败原因：接口返回错误 code=10007：Project not exist
> 只读：本插件只发 GET，从不改 / 删评论，也不标记已读。
```

**为什么选"明说"而不是静默跳过**：静默会让 AI 把"读不到"当成"设计师没留言"，那正是本项目最忌讳的失败模式。
代价是：**这种情况下输出比旧版多这一段**（旧版根本没有评论段）—— 这是**有意**的，返回体里同时带机器可读的 `commentsError`，不用解析文本就能判断。

## 机器可读字段

有评论时，`lanhu_read_blocks` 的返回多一个 `comments` 键（没有评论 / `comments:false` **不带这个键**）：

```jsonc
"comments": {
  "total": 1, "unread": 1, "fetched": 1, "pages": 1, "truncated": false,
  "items": [{
    "id": "…", "content": "要个png的图片",
    "user": { "id": "…", "name": "qzdesign01", "nickname": "管理", "display": "管理" },
    "version": { "id": "88e0aaa6-…", "info": "版本2" },
    "unread": true, "createdAt": "2026-10-09T23:17:56.000Z", "updatedAt": "…",
    "position": { "x": 0.3217459008974022, "y": 0.2596585570581626 },   // 接口原样（归一化）
    "point":    { "x": 120.65, "y": 210.84 },                           // 换算后的稿上坐标
    "blockLabel": "Section - ModalDialogCard",                          // 平铺，最常用的那个
    "anchor": { "hit": true, "reason": "hit", "distance": 0,
                "block": { "uid": 1, "label": "…", "kind": "card", "x": …, "y": …, "w": …, "h": … },
                "layer": { "name": "生成男士职业照 1", "type": "shapeLayer", "w": 120, "h": 152 } },
    "replies": []
  }]
}
```

`anchor.reason` 的四种取值：`hit`（命中）/ `near`（未命中、只给最近的块当线索）/ `blank`（未命中且附近没块）/ `no-position`（评论没带定位坐标）。
接口的 `user` 对象**不原样透传**（真实响应里有 20 个字段：`bind_mobile` / `mobpush_reg_id` / `open_id` …，与需求无关）。

## 实测与未验

- 真机样本：**1 张稿 / 1 条评论**（「人才弹窗」的「要个png的图片」）—— 上例就是它的真实输出；
  落点是弹窗卡片，块内最细层正是职业照图片层，与评论内容对得上。
- 其余路径（分页、失败降级、`(0,0)` 没定位、空白落点、同框副本、超长正文、上限夹取）全部由**离线自检**用**真机结构的 fixture** 覆盖。
- **没有**在评论量很大的稿上实测过（手上的账号只有 1 条评论），分页只验到了 mock 的第 2 页与硬上限。
- **回复串**只验到解析与渲染（fixture 里自造 1 条）；手上这张稿的 `replies` 是空的。
