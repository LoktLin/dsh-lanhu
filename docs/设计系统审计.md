# 设计系统审计：这个项目的设计漂了吗

> 返回 [README](../README.md) ｜ 完整参数见 README 的「工具」一节。

## 为什么要有它

蓝湖**按稿组织**，不按"组件"组织 —— 所以"同一颗主按钮在 12 张稿里长出 5 种圆角"这件事，
在蓝湖里没有任何一屏看得出来。而这个插件已经能全量读取图层，这件事该由它回答。

```json
{ "projectId": "…", "limit": 20 }
```

```bash
lanhu audit --url "<项目链接或任意一张稿的链接>" --limit 20
```

`limit` 是**安全阀**，不是礼貌参数：**扫 N 张稿 = 2N 次请求**（1 次稿详情 + 1 次图层树）。
实测 1437 张 ≈ 45 分钟。所以默认只扫 50 张，`limit` 可以加，但**永远不会超过硬上限 200**。
输出里必定写明 `scanned / total / truncated`。

## 输出长什么样

真实一次调用（252 张稿的项目，只扫 10 张）：

```
# 设计系统审计 — 105福建省碳足迹公共服务平台

· 扫描：**9 / 10 张**已尝试、项目共 **252** 张 → **已被上限截断**（本次上限 10；默认 50、硬上限 200）
· 读到图层：9 张 · 块 2273 个 · 跳过 1 张（Sketch 插件格式但取不出图层（已按同一套规则试过归一化） 1）
· 命名基础：可靠块名 **1051/2264** 块（46%）· 工具默认名 1213 · 空名 0
· 判据：同一组件 = **层名归一化后相同（NFKC + 折叠空白 + 转小写）**；工具默认名（`Rectangle 12` / `矩形 3`）与空名**一律不认**（不硬凑）。

## ① 同一组件、多种规格
· **定位** 高度：16px（7 张） · 20px（6 张）
  → 建议以 **16px** 为准（多数派 7/13 块）
  · 例：16px → …、6.1.1双碳资源_首页、…（等 7 张）
  · 例：20px → …（等 6 张）
· 参与：53 个组件名 / 688 块；未参与：工具默认名 1213 块 · 空名 0 块 · 单张稿或样本太少 363 块

## ② 字号阶梯
· 全项目 **17** 种字号（共 926 处）：18px（272） · 22px（178） · 14px（169） · …
· 只出现 1 次的 **2** 种：19 / 59
  → 建议收敛：19→18、59→60（"常用档" = 出现 ≥ 3 次的字号）
· 常用档（出现 ≥ 3 次）：12 / 14 / 16 / 18 / 20 / 22 / 24 / 26 / 36 / 40 / 42 / 48 / 50 / 60 / 100

## ③ 色值漂移（近重复色）
> 口径：RGB 欧氏距离 ≤ 12 视为"肉眼分不出"；只在**同一透明度**之间比较。
> 聚类：完全链接：簇内**任意两个**都 ≤ 阈值。
· #dddddd（67 块 / 7 张 · bg/border） ≈ #d9d9d9（9 块 / 5 张） ≈ #d8d8d8（6 块 / 2 张） · 组内**任意两个**都 ≤ 8.66
  → 建议统一为 **#dddddd**（多数派；共 82 处）
  · 例：#d9d9d9 → 大屏组件、附件、6.1.1双碳资源_首页、…
```

五个小节，每一项都给「**结论 + 计数分布 + 哪几张稿**」：

| 小节 | 回答什么 | 依据 |
|---|---|---|
| ① 同一组件、多种规格 | 同一颗按钮/卡片在不同稿里的**圆角、高度**有几种，该以哪个为准 | **层名**（见下） |
| ② 字号阶梯 | 全项目几种字号、哪些只出现 1 次、能收敛到哪一档 | 块的 `font.size` |
| ③ 色值漂移 | 哪些色值**肉眼分不出却写了两套** | 色值之间的 RGB 距离 |
| ④ 间距尺度 | 出现哪些间距值、哪些不在 4px 栅格上（**参考项**） | 几何相邻间距 |
| ⑤ 圆角家族 | 圆角值分布、哪些不在常见刻度上（**参考项**） | 块的 `radius.max` |

**没有漂移时明说「未发现漂移」**（不是静默空输出）；某一类没有发现时那一小节自己也会说清楚。

## 「同一个组件」怎么认：只有一条判据

**层名归一化后相同** = 同一个组件。归一化 = NFKC（全角→半角）+ 折叠连续空白 + 去首尾 + 转小写。
**不剥尾号**：`主按钮` 与 `主按钮 2` 是两个层，硬并会造出假的"多种规格"。

**名字不可靠的一律不认**（明确排除，并计数进"未参与"）：

| 类别 | 例子 |
|---|---|
| 工具默认名 | `Rectangle 12` · `矩形 3` · `Group 5` · `Path 3×8` · `Frame 427` · `椭圆 2` |
| 复制体 | `Rectangle 3 Copy 37` · `矩形备份 6` · `副本 2` |
| 纯编号 / hash / 短名 | `50` · `A1` · UUID · `底`（归一化后 < 2 字） |
| 空名 | `''` / 只有空白 |

反过来，**真名不会被误伤**：`MainFrame`、`CardGroup`、`icon-arrow`、`按钮-primary`、`关键字：` 都算可靠 ——
判据是**整个名字**（首尾锚定），不是"含不含有某个词"。

参与门槛（都在 `LIMITS` 里）：一个组件名至少**跨 2 张稿**且**有 3 块**才算进 ①。
不够的块照实计数成「单张稿或样本太少」，**不静默丢掉**。

## 可靠度：什么时候这份报告不能信

判据（阈值全部在 `LIMITS`，输出里也写）：

| 判据 | 结论 |
|---|---|
| 成功读到图层的稿 < 2 张 | 不可靠：样本太少，跨稿结论没有意义 |
| 一个可审计的块都没读到 | 不可靠：多半是整页 jpg 图片型条目，那里没有"设计系统"可谈 |
| 可靠块名占比 < 30% | 不可靠：**命名不可靠** —— 大半是 `Rectangle 12` 这种工具默认名 |

**不可靠时默认一项明细都不出**，只交代依据与下一步：

```
⚠️ **本项审计不可靠 —— 不出明细。**
· **命名不可靠**：可靠块名只覆盖 0/12 块（0%，低于 30%）—— 其余是 `Rectangle 12` 这类工具默认名或空名。
· 为什么不出明细：跨稿"同一组件"的判据是**层名**；名字大多是工具默认名时，
  按它归组会得到"5 种圆角"这种**看着精确、其实认错组件**的结论 —— 比不给更糟。
```

不可靠分两种，**下一步不一样**：

- `primaryReason: "naming"` —— 让设计师把关键组件的层名规范化后重跑；
  或者传 `allowWeakNaming: true`，只放开**不依赖层名**的那几项（② ③ ④ ⑤），并明确标注「组件规格一项已跳过」。
- `primaryReason: "sample"` —— 这些稿本来就没有图层（整页图片；或 Sketch 插件格式里 `info[]` 取不出子层的那种），
  换一个有图层数据的项目；`allowWeakNaming` 在这里**不放开**（没数据可出，放开只会印一堆 0）。

## 几条刻意的取舍（都是实测逼出来的）

| 取舍 | 为什么 |
|---|---|
| **① 只比"圆角 / 高度"，不比宽度** | 宽度常随布局变（整宽 / 半宽），拿它当"规格漂移"会满屏假发现 |
| **① 的高度不看文本层** | 文本层高度由文案长短与换行决定（实测 `关键字：` 的 100 个块里 18 与 20 混着出现）——文本的规格看字号 |
| **③ 只在同一透明度之间比** | `#4693ff` 与 `#4693ff@60%` 的 RGB 距离是 0，但一个是实色、一个是 60% 描边，聚成一簇并"建议统一"是假发现 |
| **③ 用完全链接而不是连通分量** | 连通分量会连成链（`#ffffff ≈ #f9f9f9 ≈ #f2f2f2 ≈ …`），最后一簇最大距离冲到 32.89 —— 那时"肉眼分不出"就是假话 |
| **④ 只统计 ≤ 120px 的间距** | 几百 px 的"间距"是版面留白，不是尺度 token |
| **④⑤ 只标"参考项"** | 4px 栅格与圆角刻度是**常见约定**、不是硬规范（大屏/自由排版项目常常不在栅格上）——只报分布，不下判决 |
| **单张稿失败不炸整次审计** | 逐张记录跳过原因，并翻成人话（"没有图层数据" ≠ "插件坏了"） |

## 在面板上用（不用记命令）

侧栏「蓝湖」→ **体检** Tab → 一致性区：选项目（或贴链接）→ 填「扫描张数」→ 「开始审计」。
面板默认 **20 张**（比工具的 50 更克制），并在按钮上方直接算出 **本次约 N 次请求**、写明硬上限 200 ——
成本摆在落手之前，不靠用户记文档。张数在客户端和 Host **各夹一次**（输 5000 也只发 200）。

| 纪律 | 面板上的样子 |
|---|---|
| 成本必须受控 | 张数输入框 + 「成本 = 张数 × 2 次请求，本次约 N 次；硬上限 200」；结果抬头里照旧写明 `扫描 x/y 张（被上限截断）` |
| 长任务要有反馈 | 按钮变「审计中…」并禁用，下面一行 `⏳ 正在扫描 N 张稿（约 2N 次蓝湖请求，已用 12s）…`；另有「取消」 |
| 不可靠时拒绝出明细 | 结果区**上方**一条 ⚠️ 横幅（`role="alert"`）：写明"N 张稿里只读到图层的比例 / 可靠块名 647/926"这类**证据**，并让五类结论**每一项**都显示「未出（不可靠）」而不是空白 —— 空白会被读成"没有漂移" |
| 取消的语义要诚实 | 「取消」= 面板不再等、这次结果作废；**Host 那一次扫描会自然跑完**（蓝湖请求本身不支持中断），所以要少花钱请调小「扫描张数」 |

## 已知空缺

- ~~**蓝湖 Sketch 插件格式的稿子读不了**~~ **2026-10 已解决**：这类稿子（`type: sketchPlugin`，图层平铺在 `info[]` 里）
  实测占某项目**一半以上**，现在由 `normalizeSketchPluginTree` 归一化成与常规稿**同形**的树，
  审计/读稿/diff/切图**走同一条链**，不再整类跳过。
  只有"归一化后仍取不出子层"的那种才单列一类跳过（抬头里会说明，且点明是**已知空缺**、不是"这些不是设计稿"）。
  ⚠️ 旧版本对它们会**静默返回"共 1 块：画板"**（看着成功、其实什么都没解析）—— 现在各入口一律**明说**。
- **整页 jpg 图片型条目**没有图层数据（`lanhu_list_designs` 里带 `.jpg` 的那批），同样跳过并计数。
- **成本随张数线性增长**：审计不做增量、不缓存；每次调用都是 1 + 2N 次请求。
