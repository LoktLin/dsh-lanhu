# 产品文档 / 原型（PRD）

> 返回 [README](../README.md) ｜ 完整参数见 README 的「工具」一节。

蓝湖里有两类东西，**长得很像但完全不是一回事**。拿错工具不会报错，只会让你读到一堆对不上的数据：

| | 设计稿 | 产品文档（原型） |
|---|---|---|
| 蓝湖里的样子 | 一张张切好的图 | Axure 导出的可点击原型 |
| 链接特征 | `image_id=…` | `docType=axure`、`docId=…`、`pageId=…` |
| 回答什么问题 | 什么颜色、几 px 圆角、什么字体 | 业务规则、字段有哪些、点了跳去哪 |
| 用什么工具 | `lanhu_read_design` / `lanhu_read_blocks` | **`lanhu_list_product_documents` / `lanhu_read_product_doc`** |

拿错的表现：用 `lanhu_read_design` 读原型，会得到「1 层」这种**看起来像结果**的垃圾。
所以插件**主动拦**——识别出原型树时会明确报 `PROTOTYPE_NOT_DESIGN` 并指路，不静默给空结果。

---

## 一、先列，再读

```jsonc
// 1) 看项目里有哪些原型文档
{ "url": "https://lanhuapp.com/web/#/item/project/product?tid=…&pid=…&docId=…&docType=axure" }
// → lanhu_list_product_documents
```

返回每份文档的 `docId` / 名称 / 更新时间 / 最新版本 id / 版本数 / 是否已替换，外加项目名、文件夹、创建者。

```jsonc
// 2) 读页面树（**先不带 pageId**）
{ "projectId": "…", "docId": "…", "teamId": "…" }
// → lanhu_read_product_doc
```

一份原型常有**上百个页面节点**（实测某份是 **219 个节点 / 183 个可读页**），
全量抓正文既慢又没用 —— **先看树，再选页**。

## 二、选中一页

| 传什么 | 行为 |
|---|---|
| `pageId` | **推荐**。精确匹配，且 **pageId 跨版本稳定**（同页在不同版本里 id 不变） |
| `pageName` | 模糊匹配（包含即命中，可能命中多页） |
| 都不传 | 只返回页面树，不抓正文 |

`limit` 控制最多读几页正文（默认 1）。命中不了会报 `PAGE_NOT_FOUND`，**不会静默返回空**。

## 三、正文从哪来（这条很关键）

实测结论，别踩：

- **`data.js` 里往往没有内容**。本项目实测的原型，`data.js` 的 `page.diagram.objects` 全是 `vectorShape` / `connector`，
  `label` 空、无文本、无标注 —— 因为原稿是以**矢量/图片**形式导出的。
  **只解析 `data.js` 会得出「这页没内容」的假结论。**
- **正文在页面 HTML 里**，而且是 **HTML 实体编码**的（`&#x9996;&#x9875;` = 首页）。
  所以本插件两条路都走：`data.js` 有原生控件就用，没有就从 HTML 抽可见文本（自动解实体、剥 script/style、去重）。
- 资源地址 = **`https://axure-file.lanhuapp.com/{sign_md5}`**。
  `sitemap`/`pages` 里给的是**相对路径**（`src`），那个**取不到**（404）；要用 `sign_md5` 当路径。

实测一页能取到 35 条真实业务规则（「1、排序规则」「根据排序值显示 1、2、3、4…」）。

## 四、docId 失效会自动找回

原型被**重新上传**后，链接里冻结的旧 `docId` 会失效，蓝湖回 `code=10009 Image not exist`。

插件不会把这个错误直接丢给你，而是：

1. 用 `product_documents` 列出项目里的 axure 文档；
2. **1 份** → 直接用；
3. **多份** → 逐个拉 sitemap，用 **`pageId` 命中**来消歧（pageId 跨版本稳定）；
4. 仍定不下来 → 报错并**列出全部候选**（`docId=… 名称=…`），让你用列表工具选定。

同一条逻辑 `lanhu_read_design` / `lanhu_read_blocks` / `lanhu_read_product_doc` 共用。

## 五、指定版本

`lanhu_read_product_doc` / `lanhu_read_design` / `lanhu_read_blocks` / `lanhu_download_slices` 都接受 `version`：

- 不传 = `latest`。结果里的 `version` 字段会**写明实际用了哪一版、是不是最新版** ——
  否则稿子一更新，「我照着这版做的」就悄悄失去依据了。
- 传了具体 id **必须命中**，命中不了报 `VERSION_NOT_FOUND` 并列出最近的版本 id。
  **绝不静默回退到 latest**（静默回退比报错更坏：你会以为拿到的是指定版本）。

## 六、这一页的样式也能读（`format: "layers"`）

正文回答"业务规则"，**样式**回答"长什么样"。同一条原型链接加 `"format":"layers"` 即可：

```
lanhu_read_product_doc {"url":"<原型链接>","format":"layers"}          # 该页的图层/块级清单
lanhu_read_product_doc {"url":"<原型链接>","format":"layers","layerLimit":200}
```

输出**与设计稿的块级清单是同一张表**：绝对坐标 / 尺寸 / 圆角 / 底色 / 文字色 / 字号 / 字重 / 字体族 /
行高 / 透明度 / 描边 / 渐变 stop / 切图 / 层级 —— 所以 AI 不必学第二套。

**什么时候用它**：项目里**没有设计稿**（`lanhu_list_designs` 返回 0 张）、只有原型时，这是唯一能拿到
"照着做"所需数值的路。**但要知道它的成色**：

- 原型里的颜色/字号是**设计者在 Axure 里随手填的**，不是设计系统里的值；**有设计稿时一律以设计稿为准**。
- 部分文本层**导出里就没有字号** → 输出显示 `?`。**别把 `?` 读成 0，也别自己猜一个**。
- 动态面板的**备选状态**会一并列出（互斥、不是同时显示），导出里**没有"当前是哪个状态"的字段**，要按业务自己判断。

细节与计数口径见 [原型样式.md](原型样式.md)。

## 七、和原型无关的两件事

- **`dds`（设计数据服务）**：另域 `dds.lanhuapp.com` + 独立 Cookie 的**非官方通道**，
  随时可能失效。本插件**不把它当主路径**，也没接进工具链。
- **产品文档 ≠ 需求文档全文**：这里读的是原型页面上的文本与标注。
  若需求写在附件/文档里，走蓝湖的文档模块，不在本工具范围。
